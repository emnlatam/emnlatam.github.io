# EMN — Escuela de Música y Negocios

Jekyll static site on GitHub Pages, served at **https://emnlatam.github.io** (home page lives at `/emn/`). Repo: `emnlatam/emnlatam.github.io`.

AMBRA now lives entirely separately in the original repo, under a different GitHub account. Never mix the two projects' files, Supabase projects, or credentials again.

**Repo naming matters**: this repo must stay named exactly `emnlatam.github.io` (matching the `emnlatam` account name exactly) — that's the only way GitHub Pages serves it at the domain root instead of under a `/reponame/` subpath. Learned this the hard way during the migration.

## Push workflow

The user pushes via **GitHub Desktop**, signed in as the `emnlatam` GitHub account (a different account than the one used for AMBRA — GitHub Desktop only supports one GitHub.com account at a time, so switching projects usually means switching signed-in accounts too). By default the user writes their own commit messages — don't run `git commit` on their behalf; only stage changes for review.

**Exception — only when the user explicitly asks** (they may do so from their phone while the computer stays on): you may `git add` + `git commit` and/or `git push origin main`. Never do any of these on your own initiative, and never amend or force-push. For a commit: run `git status` first, stage only what belongs to the request, use the message the user gives (or, if none, a short lowercase Spanish one in the style of the history: `contrasena recap`, `style career`), and add the Claude co-author trailer unless they say not to. Report the result. `.claude/settings.local.json` (gitignored, personal) pre-approves add/commit/`push origin main` so the phone doesn't need approval taps, and makes `--amend`, `add -f` and force-push variants ask. Asking for a commit does not imply a push, nor the reverse — do only what was asked. A terminal push needs a stored credential for the `emnlatam` account (GitHub Desktop's login isn't shared with the terminal); if `git push` fails with an auth or `/dev/tty` error, say so and hand the push to the user in GitHub Desktop rather than working around it.

## Site conventions

- Permalinks are root-level with **no trailing slash** (e.g. `/practice-lab`, `/career`, `/usuarios`, `/career-progress`), except the home page which is `/emn/` (trailing slash, historical).
- Every layout's `<head>` includes `_includes/emn-favicon.html` (the EMN logo as the browser-tab icon, `assets/img/favicon.png`) — add it to any new layout.
- Static assets use cache-busting: `?v={{ site.time | date: '%s' }}`.
- `assets/js/emn-auth.js` is the shared client — every page loads it after the Supabase JS CDN script. It exposes `emnSession` / `emnStudentProfile` (both null when signed out — sign-in is optional almost everywhere) after `emnInit()` resolves, and injects nav dropdowns by hand (not via each page's own HTML): "Mi Aula" (any signed-in person: Calendario, Career Progress) and "Administrar" (admin/professor only; a plain link to `/administrar`, no dropdown), plus the account/login link. When signed in it also splits the Practice Lab dropdown's "Interview Prep" into Practice (`/interview-prep`) and Questions (`/clases-interview-prep`). The static part of the header (logo → home, no "Inicio" tab; Practice Lab dropdown) lives once in `_includes/emn-header.html`, included by every layout with a header. It also owns a self-contained in-page modal system (`emnConfirm()`, `emnOpenAccountModal()` for name/photo/password) injected via JS so no page needs its own modal CSS/HTML.
- **Forgot password** lives on `/emn-login` ("¿Olvidaste tu contraseña?"): `resetPasswordForEmail` with `redirectTo` = `https://emnlatam.github.io/emn-login` (must stay in Supabase's Redirect URLs allow-list, same as the invite). Supabase only emails addresses that already have an account, and the form answers identically either way so it never reveals who is enrolled. There is no self-signup.
- **No tab flicker**: the nav tabs injected by `emn-auth.js` (Mi Aula, Administrar, account/login link, split Interview Prep) depend on the async session, so the last-known state `{in, role, name}` is cached in `localStorage` (`emn.nav`) and drawn at DOMContentLoaded (`emnRenderNav`); `emnInit()` only redraws if the real session differs (signed-in cache but no session → one reload). Injected items are marked `data-emn-inj`, and their caret toggles use `stopImmediatePropagation` so a page's own caret wiring can't toggle twice.
- Clicking outside any floating panel closes it (global handler in `emn-auth.js` for `<dialog>` backdrops and `.overlay.open`).
- **All popups are in-page modals**, never the browser's native `alert()` / `confirm()` / `prompt()`: use `emnAlert()` / `emnConfirm()` from `emn-auth.js` (the user asked for this explicitly). The one unavoidable exception is the browser's own prompt when closing/reloading a tab with unsaved changes (`beforeunload`), which browsers don't let pages restyle.
- Sign-in is optional on most tool pages (Sight Melody, Interview Prep practice tool) — they work the same signed in or out, just don't log practice time when signed out.

## Notable features

- **Sight Melody audio** (`/sight-melody`): playback fetches piano samples from `assets/sounds/piano/<Note><Octave>.mp3` (flat spelling, e.g. `Db4.mp3`; all 88 keys A0–C8, ~2.2 MB). They were missing after the repo split (the files stayed in the AMBRA repo) and every note 404'd, so nothing played — if the melody ever goes silent again, check these URLs first.
- **Sight Melody Live Mode** (`_layouts/emn/sight-melody.html`): two-way real-time sync between a professor and a student over Supabase Realtime Broadcast (no DB table, ephemeral channel keyed by a short join code). Uses a seeded PRNG (`rngFn`, swappable, seeded via `mulberry32`) so both sides render the *exact* same generated exercise from a tiny `{state, seed}` payload instead of syncing the whole generated note data. Dictation Mode is the one deliberate exception that stays local to each person (never touches shared `state`).
- **Career Progress** (`/career-progress`): a multi-category tracker (songs, social content, TV, press, press kit, portfolio, contests, volunteering) with per-row "stage" progress tracks, CSV/Excel export, and Supabase persistence per student. Admin/professor get a student dropdown (or `?student=<id>`) to open and edit any student's tracker.
- **Cursos** (`/cursos`, editor at `/cursos-editor`): paid video courses with their own dashboard (no site header) and a LearnWorlds-style viewer. Tables `courses`, `course_lessons` (public outline; `kind` video/quiz, `is_free`), `lesson_videos` (the protected content: `video_url` or `quiz` JSON), `course_access`, `lesson_progress`. **These are the one exception to the RLS-disabled convention** — RLS is what keeps unpaid people from reading lesson content; schema and policies are in `supabase/sql/cursos.sql`. Access is granted by a `course_access` row; "Desbloquear" opens `courses.payment_url` (Stripe Payment Link). Staff can preview as a non-buyer with `?as=visitante`.
- **Home** (`/emn/`): dark pinned header (`_includes/emn-header.html`, `variant="dark"`), then the dark hero, then a white banner ("Obtén una evaluación gratuita…") with an "Agendar" button to EMN's Calendly (`https://calendly.com/emnperu/30min`, taken from academy.emnlatam.com). The banner sits at the bottom of the first screen and, once scrolled to, pins under the header (on phones the header scrolls away and only the banner pins). Then, in order: the "El costo de no prepararse…" section, the mentors block, the audition section (gray band), a red "EMN desarrolló sus propias aplicaciones…" banner with a button to `/practice-lab`, the four services cards ("Clases y mentorías especializadas", one border colour each), a partners section (`_data/partners.yml`; logos go in `assets/img/partners/<id>.png`, without a logo the name is shown as text), and the closing banner. All the big titles share one size through the `--title-feature` CSS variable — use it for any new big title. Drop a transparent PNG at `assets/img/hero.png` and it appears on the right of the hero automatically. The hero's background is `assets/videos/emnvideohead.mp4` (falls back to the first `.mp4` in that folder; autoplay/muted/loop; phones, reduced-motion and data-saver users skip the video) with `assets/img/hero-poster.jpg` — a frame of that video — shown instantly underneath while it loads, so keep the video compressed and regenerate the poster if the video changes. The page ends with a full-width closing banner ("La audición puede cambiar tu vida para siempre. ¿Estás preparado?", the contact line, and a **Postula** button that opens a short form in a native `<dialog>`: nombre y apellido / correo / WhatsApp / link de un video tocando — all text fields) whose background is `assets/img/boston.*` over a dark scrim.
- **Administrar** (`/administrar`): five buttons — Comunidad, Calendario, Actividad, Usuarios, Invoices — that switch the view in place (no page change): the section loads in an iframe with `?embed=1` (`emn-auth.js` hides the site header and `a.back` links in that mode and forwards internal link clicks to the parent via `postMessage`), and the buttons shrink into a tab bar above it; It always opens straight on the Comunidad view with the button bar on top (no remembered section / no hash deep links); the big four-box landing only shows if no view is set. Each section is still a normal page at its own URL. The course editor (`/cursos-editor`) is reachable only from the Cursos page ("Editar cursos", staff only). The old `/admin-calendar` (per-student to-dos, same `career_todos` rows the student sees on `/career`) is no longer linked from any menu.
- **Comunidad** (`/comunidad`, in-page sub-buttons Alumnos / Profesores / Postulaciones that only switch the view, no navigation — Postulaciones moved here from Administrar (`/postulaciones` still exists but is unlinked); Profesores = Airtable "Professors info", table `profesores`, and the student form picks "Assigned Teachers" from it) + **Calendario** (`/calendario`): tables `alumnos` (nombre/correo/whatsapp + `datos` jsonb for the other Airtable fields, `cursos[]`, `color`, `airtable_id`), `clases` (alumno, curso, fecha, hora, link); per course a student also has a teacher (`profes_curso`) and classes per month 1–8 (`clases_mes`) and `cursos_meet` (one Meet link per course); RLS staff-only (`supabase/sql/alumnos.sql`, already applied). Courses: Piece Preparation, Audio & Sight-Read, Interview Preparation, Tutoring (chosen per student) + Mock Audition, automatic on the last Sunday of every month (computed in the calendar, not stored). **Airtable sync** goes through the Edge Function `airtable-sync` (secrets `AIRTABLE_TOKEN`, `AIRTABLE_BASE_ID`, `AIRTABLE_TABLE`; staff-only): saving a student pushes to Airtable, and opening `/comunidad` or pressing the sync button pulls (Airtable wins on conflicts). Field names live in `_data/alumnos_campos.yml` — **the listed fields are placeholders until matched to the real "Students Info" columns**.
- **Archived students**: `alumnos.activo` (boolean, default true). Unchecking "Alumno activo" in the student form (or the Archivar/Reactivar button) archives them: listed last in Comunidad under "Archivados", in gray, hidden from the Calendario, still selectable in the invoice picker under an "Archivados" group.
- **Invoices** (`/invoices`, Administrar → Invoices): two sub-buttons. *Generar invoice* picks a student and builds the invoice from their saved data (courses, classes per month `alumnos.clases_mes`, duration, total cost) plus online courses they have access to (`course_access`) and Stripe payment link(s); it can split the payment into at most 2 installments, producing two invoices ("Pago 1 de 2" / "Pago 2 de 2", each with its own link). PDFs are generated in the browser with jsPDF (real text, not images; EMN logo; **teacher names are never shown**) and end with the terms and conditions from `_data/terminos.yml` (edit that file to change them). The generator has a **live preview** panel beside the form (sticky on screens ≥1150px): it builds the real PDF with the same `buildPdf()` into a blob URL in an iframe (debounced; Pago 1/Pago 2 tabs when split; number shown as EMN-XXXX until created). *Finanzas* lists every invoice (table `invoices`, one row per payment, `datos` jsonb = snapshot so the PDF can be regenerated): typing the payment date marks it as paid, shows collected / pending totals per currency, and exports a CSV for Excel. RLS staff-only (`supabase/sql/alumnos.sql`).
- **Postulaciones** (form on the home page → table `postulaciones`, admin list = the Postulaciones sub-button of Comunidad): visitors can only INSERT; only admin/professor can read, change `estado` (nuevo/contactado/descartado) or delete — enforced by RLS (another deliberate exception to the RLS-disabled convention, because it stores personal data; schema and policies in `supabase/sql/postulaciones.sql`). The form has a honeypot field and DB length checks; there is no email notification, so check `/postulaciones` for new entries.
- **Mentores** (`_includes/emn-mentores.html`, shown on the home page and on its own page `/mentores`): card grid with a biography that drops open under the clicked card's row (accordion sections on brand red). Content lives in `_data/mentores.yml` (id, name, role, summary, sections — copied verbatim from academy.emnlatam.com/mentores); adding a mentor is copying a block there, no HTML. Each person's photo is `assets/img/mentores/<id>.jpg` (or .png/.webp) — missing photos fall back to initials. Keep those web-sized (~1600px max, well under 500 KB): the heavy originals live as `assets/img/*_img.*`, which `_config.yml` excludes from the published site. Optional `photo_position: 36% top` in the yml re-frames a photo that crops badly. `/mentores` adds a banner with `assets/img/mentores-hero.jpg` (any extension). `/mentores#<id>` opens a biography directly. The footer is the shared `_includes/emn-footer.html`.
- **Nosotros** (`/nosotros`, layout `_layouts/emn/nosotros.html`, linked from the header instead of Instagram): the founder's story (Berklee Perú, alliances with MIT/Harvard, why EMN exists) in first person as Daniel Dávila, drawn from his CV. Text is written directly in the layout; styles are the `n-*` classes at the end of `emn.css`.
- **Clases Interview Prep** (`/clases-interview-prep`): fixed set of real English audition questions, each unlocked by Spanish "preguntas previas" tagged into one of 7 thematic "gemas" (Capacidad, Motor, Origen, Progreso, Identidad, Vision, Comunidad), with AI-assisted conclusions/drafts. Admin/professor can view and edit a specific student's answers via `?student=<id>` (from a "Ver Interview Prep" link on `/usuarios`), gated by role check.
